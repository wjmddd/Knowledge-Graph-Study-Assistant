### 1. 选题背景与意义

**1.1 选题背景**
《计算机系统基础》作为计算机专业的核心基础课程，旨在揭示高级语言程序如何在底层硬件上执行的本质，涉及硬件逻辑、指令系统、汇编语言及操作系统等多个抽象层级。该课程概念繁多（如流水线、虚拟内存、缓存一致性等），且各知识点间存在复杂的依赖与映射关系。传统的线性教学模式和基于关键词的检索方式难以直观展示这些跨层级的关联，导致初学者往往难以构建完整的系统观，容易陷入碎片化学习的困境。

与此同时，以大语言模型（Large Language Model, LLM）为代表的生成式人工智能技术正在重塑教育领域。LLM 具备强大的自然语言理解与生成能力，能够为学生提供个性化的答疑服务。然而，通用 LLM 在面对特定领域的专业问题时，存在“幻觉”（Hallucination）现象，且难以提供可溯源的精确知识，无法满足严谨的计算机系统教学需求。

**1.2 研究意义**
本研究旨在构建一个基于知识图谱（Knowledge Graph, KG）与检索增强生成（Retrieval-Augmented Generation, RAG）技术的智能学习助手，具有重要的理论意义与应用价值：

1.  **理论意义**：探索将非结构化的计算机系统教材转化为结构化领域本体的方法。通过定义 Concept（概念）、Hardware（硬件）、Instruction（指令）等特定节点类型，构建从底层硬件到上层软件的知识语义网络，为计算机系统领域的知识表示提供新的视角。
2.  **实践价值**：
    *   **提升学习效率**：通过可视化图谱展示知识点间的 `DEPENDS_ON`（依赖）、`COMPOSED_OF`（组成）等关系，帮助学生快速理清知识脉络。
    *   **增强问答准确性**：结合图谱检索与向量检索的混合策略，利用 RAG 技术显著降低 LLM 的幻觉率，提供精准、可溯源的教学解答。
    *   **辅助教学创新**：系统提供的智能问答与可视化功能，可作为传统课堂的有力补充，推动“人工智能+教育”模式的落地。

### 2. 国内外研究现状

**2.1 知识图谱构建技术现状**
知识图谱构建主要包含实体识别（NER）和关系抽取（RE）两个核心步骤。传统的构建方法多依赖于 BERT、BiLSTM-CRF 等监督学习模型，需要大量的人工标注数据，且泛化能力有限。近年来，随着 LLM 的兴起，基于生成式模型的零样本或少样本信息抽取成为研究热点。研究表明，利用 LLM（如 GPT-4, DeepSeek, Qwen）配合强类型的结构化约束（如 Pydantic, JSON Schema），能够从非结构化文本中高效抽取复杂的三元组信息。然而，如何处理长文档中的上下文依赖及跨段落的实体共指消解，仍是当前研究的难点。

**2.2 教育知识图谱与智能导学系统**
在教育领域，知识图谱已被广泛应用于个性化推荐、学习路径规划等方面。目前的教育图谱多集中于数学、英语等基础学科，针对计算机系统等工程类强关联学科的研究相对较少。现有的智能导学系统大多基于规则匹配或简单的文本检索，缺乏对知识深层逻辑的推理能力。虽然部分系统引入了 LLM，但大多仅作为聊天机器人使用，未能将教材的逻辑结构与模型的生成能力深度融合。

**2.3 RAG（检索增强生成）技术进展**
RAG 技术通过在生成回答前检索相关上下文，有效缓解了 LLM 的知识过时和幻觉问题。早期的 RAG 主要基于向量数据库进行语义相似度检索（Vector Search）。近期，微软提出的 GraphRAG 概念引发关注，即利用知识图谱的结构信息辅助检索，能够捕捉实体间的多跳关系（Multi-hop Reasoning）。然而，单纯的图检索或向量检索均存在局限性，如何设计高效的“图+向量”混合检索策略，以兼顾语义覆盖面与结构精确度，是当前 RAG 领域亟待解决的关键问题。

**2.4 现有研究不足与本课题切入点**
综上所述，现有研究在通用领域的图谱构建和 RAG 应用上已取得进展，但在计算机系统基础这一特定垂直领域，仍存在以下不足：1）缺乏针对系统底层原理的精细化本体模型；2）在处理教材长文本时，知识抽取的准确率与去重机制有待优化；3）缺乏结合图结构与向量语义的混合检索在教学场景下的深度应用。本研究将以此为切入点，设计并实现一套针对该课程的专用智能学习助手。

### 3. 研究内容与目标

**3.1 总体目标**
本研究旨在设计并实现一个集知识管理、可视化展示与智能问答于一体的《计算机系统基础》学习助手。系统能够自动从 PDF 教材中抽取结构化知识，构建高质量的领域知识图谱，并通过多轮对话形式为学生提供精准的概念解释、关系梳理及学习路径推荐。

**3.2 具体研究内容**

1.  **领域本体建模与知识图谱构建**
    *   针对课程特点，设计包含 Concept、Hardware、Instruction、Principle、CodeSnippet 五类核心节点，以及 DEPENDS_ON、IS_A、CONTRASTS_WITH 等十余种关系的模式层（Schema）。
    *   研究基于 LLM 的自动化信息抽取管线，利用 MinerU 工具处理 PDF 文档，结合 DeepSeek/Qwen 模型实现知识三元组的结构化提取。
    *   研究基于规则与语义相似度的两阶段节点融合策略，解决同一概念的指代不一致问题。

2.  **多模态数据存储与文档结构化**
    *   构建“文档-章节-文本块”的层级索引结构，实现知识点到原文的精确溯源。
    *   利用 Neo4j 图数据库存储实体关系数据，同时利用向量索引存储文本块的 Embedding 向量，为混合检索提供数据基础。

3.  **基于混合检索（Hybrid RAG）的智能问答 Agent**
    *   基于 LangChain 框架开发 Tool-Calling Agent，设计概念查询、关系推演、对比分析等专用工具。
    *   实现结合向量相似度（针对非结构化描述）与 Cypher 图查询（针对结构化关系）的混合检索算法。
    *   设计具备上下文记忆的多轮对话机制，使系统能够理解复杂的教学意图。

4.  **交互式前端与可视化展示**
    *   基于 Chainlit 搭建对话交互界面，集成 Pyvis 实现知识图谱的动态可视化渲染。
    *   开发支持 `/graph`、`/stats` 等指令的交互逻辑，展示系统的推理过程与数据统计。

**3.3 拟解决的关键问题**
1.  如何设计适应计算机系统多层级抽象特性的本体模型？
2.  如何利用 LLM 实现高精度的非结构化教材知识抽取与去重？
3.  如何融合向量检索与图检索的优势，提高复杂问题的回答准确率？

### 4. 研究方法与技术路线

**4.1 技术路线图**
本课题采用“数据驱动+模型增强”的技术路线，整体架构分为数据处理层、知识存储层、逻辑控制层与应用交互层。

*(在此处建议插入一个简单的流程图描述，文字描述如下)*：
首先利用 PDF 解析工具将教材转化为 Markdown；其次通过 LLM 进行实体与关系抽取并完成知识融合；随后将数据存入 Neo4j 与向量索引；服务端利用 LangChain 构建 Agent，动态调用图谱查询工具；最后通过 Web 前端呈现结果。

**4.2 核心研究方法**

1.  **分层上下文锚定的知识抽取方法**
    *   利用 MinerU 高保真解析 PDF，保留文档的层级结构（Chapter/Section）。
    *   采用 **DeepSeek-V3 / Qwen-2.5** 大模型，配合 **Pydantic** 定义严格的输出格式，确保抽取的稳定性。
    *   实施“层级上下文锚定”策略，在抽取底层知识点时自动关联上层章节信息，解决上下文丢失问题。

2.  **双重去重融合策略**
    *   **规则去重**：对术语进行标准化处理（如大小写归一化、去除特殊符号）。
    *   **语义去重**：利用 LLM 对相似实体进行语义判别（如识别“CPU”与“中央处理器”为同一实体），并进行中英文术语映射。

3.  **图谱+向量的混合检索机制**
    *   **向量检索**：使用 OpenAI `text-embedding-3-small` 模型对 TextChunk 进行向量化，用于捕捉自然语言中的隐含语义。
    *   **图谱检索**：编写 Cypher 模板，支持多跳查询（如“查询 A 指令依赖的硬件组件”）。
    *   **融合重排序**：Agent 根据用户意图动态选择检索工具，或同时执行两种检索并利用 Reciprocal Rank Fusion (RRF) 算法对结果进行重排序。

4.  **智能 Agent 设计方法**
    *   基于 **LangChain** 框架，定义 7 个原子工具（概念定义、组成结构、学习路径等）。
    *   利用 LLM 的 Function Calling 能力，根据用户提问（如“流水线和超标量有什么区别？”）自动路由到“概念对比”工具，而非通用的文本搜索。

**4.3 系统集成方法**
后端采用 Python 3.11 环境，使用 Neo4j 作为核心图数据库。前端采用 Chainlit 快速构建聊天界面，通过 WebSocket 实现流式输出，保证良好的用户体验。
